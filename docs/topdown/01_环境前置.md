# 环境前置

## 1. 检查目标机

| 检查项 | 要求 | 检查命令 |
| --- | --- | --- |
| CPU 和内核 | Linux。920B、950 使用 AArch64 镜像，海光、Zen 4 使用 x86-64 镜像 | `uname -m`、`uname -r` |
| GPU 和驱动 | 宿主机能识别 GPU，驱动与容器内 CUDA 运行库兼容 | `nvidia-smi` |
| GPU 规格 | 显存与计算能力满足模型和镜像要求，84 基线使用 A100 40 GB | `nvidia-smi --query-gpu=name,memory.total,compute_cap --format=csv` |
| Docker 和 GPU 运行时 | Docker 已接入 NVIDIA Container Toolkit | `docker version`、`nvidia-ctk --version` |
| CPU 与 GPU 位置 | 按实际拓扑选择 Worker、服务和客户端 CPU | `nvidia-smi topo -m`、`lscpu -e=CPU,CORE,SOCKET,NODE,ONLINE` |
| 磁盘和模型 | 留出镜像导入、模型和结果空间，模型目录包含权重、配置和 tokenizer | `df -h /home`，检查实际模型目录 |

采集容器还需访问 GPU、PMU 和 NUMA。容器启动后的检查命令见 [部署与测试](00_部署与测试.md)。

缺驱动时按系统、CPU 架构和 GPU 选择安装包，并准备与当前内核匹配的开发包。[NVIDIA 驱动安装指南](https://docs.nvidia.com/datacenter/tesla/driver-installation-guide/)

Toolkit 安装后，如果 Docker 尚未接入 GPU，由管理员在空闲时段配置并重启 Docker。[NVIDIA Container Toolkit 安装指南](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)

```bash
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

## 2. 核对 BIOS 和放置

84 的历史 Partition 对照采用以下 BIOS 值。其他机器按实际 BIOS 菜单和测试条件填写。

| BIOS 项 | 84 参考值 |
| --- | --- |
| `NUMAEn` | `Enabled` |
| `OneNumaEnable` | `Disabled` |
| `CacheMode` | `in:partition out:share` |

复现历史 920B 基线时，核对各角色的 CPU 实际频率约为 2.9 GHz，Worker、代码页、数据页和 GPU 在同一 NUMA 节点。该基线使用 4 KB 私有代码页并关闭匿名 THP。锁频和文件代码页需要在测试前单独设置并验证。
