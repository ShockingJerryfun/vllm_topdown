# 部署与测试

部署前核对 [环境前置](01_环境前置.md) 和 [版本清单](02_版本清单.md)。配置时查 [测试参数](03_测试参数.md)。

## 1. 准备代码、镜像和模型

下面以 920B + A100 为例。84 上的参考材料如下。

| 材料 | 84 路径 |
| --- | --- |
| 源码包 | `/home/fj/topdown_release/source/topdown-920b-src.tar.gz` |
| AArch64 镜像包 | `/home/fj/topdown_release/images/topdown-920b-0.26-cu130.tar` |
| Qwen3-8B 模型 | `/home/model/Qwen3-8B-Instruct` |

| 仓库文件 | 用途 |
| --- | --- |
| `scripts/run_topdown.sh` | 宿主机统一采集入口 |
| `scripts/config.env` | 公共默认参数和各平台事件组 |
| `scripts/920b/baseline.env.example` | 920B 基线配置示例 |
| `scripts/zen4/baseline.env.example` | Zen 4 基线配置示例 |

将材料放到目标机，按实际位置填写路径。选择尚未部署源码的位置解包。其他 CPU 平台使用适配本机的镜像包。

```bash
DEPLOY_DIR=/home/fj
SOURCE_ARCHIVE=/path/to/topdown-920b-src.tar.gz
IMAGE_ARCHIVE=/path/to/topdown-920b-0.26-cu130.tar

mkdir -p "$DEPLOY_DIR"
tar -xzf "$SOURCE_ARCHIVE" -C "$DEPLOY_DIR"
docker load -i "$IMAGE_ARCHIVE"
PROJECT="$DEPLOY_DIR/vllm_topdown_persistent"
cd "$PROJECT"
```

## 2. 启动采集容器

选择本次使用的 GPU 和容器名。代码目录和模型目录按相同绝对路径挂载到容器。

```bash
IMAGE=fangjin/topdown-920b:0.26-cu130
MODEL=/home/model/Qwen3-8B-Instruct
CONTAINER=topdown_920b
GPU_DEVICE=0

docker run -d --name "$CONTAINER" --gpus "device=$GPU_DEVICE" \
  --privileged --security-opt seccomp=unconfined \
  -v "$PROJECT:$PROJECT" -v "$MODEL:$MODEL:ro" \
  "$IMAGE" sleep infinity

docker exec "$CONTAINER" nvidia-smi
docker exec "$CONTAINER" perf stat -e cycles:u -- true
```

容器内应能识别选定的 GPU，且 `cycles:u` 有计数。只挂载一张卡时，测试配置中的 `GPU_ID` 填 `0`。

## 3. 配置并运行

920B 用下面的示例。Zen 4 改用 `scripts/zen4/baseline.env.example`。950 和海光可用 920B 示例作起点，在配置中选择本机的 `CHIP`。

```bash
cp scripts/920b/baseline.env.example baseline.env
```

按本机修改 `baseline.env` 中的路径、容器名和绑核值，见 [测试参数](03_测试参数.md)。示例设置 `ANON_THP_MODE=off`，先在容器中编译启动器。

```bash
docker exec "$CONTAINER" gcc -O2 -Wall -Wextra \
  "$PROJECT/scripts/thp_exec.c" -o "$PROJECT/scripts/thp_exec"
```

在宿主机的源码目录执行，结果目录使用新路径。

```bash
RESULT="$PROJECT/results/baseline_01"
bash scripts/run_topdown.sh "$PROJECT/baseline.env" "$RESULT"
```

脚本会启动 vLLM 服务和 Benchmark 客户端，按轮次采集耗时、PMU 和热点，完成后打印 Excel 工作簿路径。

## 4. 检查结果

| 文件 | 内容 |
| --- | --- |
| `920b_vllm0.26_qwen3_7k100.xlsx` | 本次测试的 Excel：`Topdown` 页为各阶段指标及 Benchmark，`Hotspot` 页为热点函数 |
| `summary.csv` | 各阶段指标汇总 |
| `collection_quality.csv` | 各阶段、各组的有效样本数和状态 |
| `hotspot/perf_report.txt` | CPU 热点 |
| 各轮 `benchmark.log` | 请求结果。920B 的 22 组模式和 Zen 4 另有 `benchmark_before/` 和 `benchmark_after/` |
| `runtime.txt`、`commands.txt` | 实际加载的组件和启动命令 |

Excel 文件名随芯片、模型及输入输出长度变化。上表为本指南 920B 基线示例；其他平台的工作表和 Benchmark 内容按实际采集配置生成。

950 和海光在未开启独立频率采集时，Excel 的 Benchmark 区当前会显示未采集；各轮的请求日志仍保存在对应的 `benchmark.log` 中。

随包提供的 `Workload_Data_920B.xlsx` 是历史多条件汇总表，供对照参考。新一轮测试会生成自己的 Excel，不会自动合入这份汇总表。

单请求输出 100 token 时，各阶段应有 99 个有效 Decode 样本，`invalid=0`、`status=ok`。PMU 样本的 `time_enabled` 和 `time_running` 应相等且大于零。启动失败时先查结果目录中的 `service/` 日志。
